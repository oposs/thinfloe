This note covers how the machine's time zone and NTP servers are chosen: the Time band of the menu, the DHCP watcher, the root files, netboot, and the tests.

## Precedence

- **System time zone:** the zone set in Settings → Network → Time, else the zone DHCP sends (option 101), else UTC. "Automatic" in the region select is the second and third case.
- **Session:** a hand-written `TZ=` in `~/.config/thinfloe/environment` still wins inside the session: `10-thinfloe-session.sh` exports it with `set -a`, so it reaches labwc, `thinfloe-session` and the menu. The Time band then says `This session uses TZ=… from ~/.config/thinfloe/environment.` An invalid `TZ=` gives UTC in the session, not the system zone, as glibc does.
- **NTP:** servers set in the menu replace all others (the Ubuntu pools and the DHCP servers). An empty field ("automatic") gives the NTP servers DHCP sends (option 42) plus the Ubuntu NTS pools. A network with its own server usually wants only that one; mixed with internet pools, which one chrony follows is hard to predict.

The NTP client is **chrony** (`chrony.service`), not systemd-timesyncd, which is not in the image. Its `chrony.conf` reads `sourcedir /run/chrony-dhcp` and `sourcedir /etc/chrony/sources.d`; Ubuntu's pools are `/etc/chrony/sources.d/ubuntu-ntp-pools.sources`. Up to 4.6.0 the DHCP servers never reached chrony: only dhclient hooks or NetworkManager write `/run/chrony-dhcp`, and ThinFloe has neither, so a network without internet access never synchronised the clock (seen on the owner's thin client 2026-11-20: the lease had `NTP=195.176.26.215`, chrony used only the pools).

## The setting and its files

The menu keeps `[time]` in `config.toml` (`zone`, absent = automatic; `ntp`, a list, empty = automatic) and renders `~/.config/thinfloe/generated/time`, mode 644, absent when both are automatic:

```
# Generated by the ThinFloe menu ...
zone=Europe/Zurich
ntp=ntp.example.ch
ntp=10.1.2.3
```

A zone is UTC or a zone of `/usr/share/zoneinfo/zone.tab` (third column); the menu offers only those, and the root side checks the list, so a path, `..` or a link name cannot pass. A saved zone the image's `zone.tab` does not list (a hand edit, or tzdata dropped it) is left out of `generated/time`, so the servers are still installed and the zone falls back to DHCP or UTC; the menu notes it once at start (`config.toml: the time zone … is not in this system's zone list`), the band shows Automatic and a warning line naming the zone, and `config.toml` keeps it until the next change in the band. A server is an IPv4 or IPv6 address or a host name (at most 253 characters, labels of 1 to 63 letters, digits and `-`, not starting or ending with `-`); at most 8.

Two root tools install it, both into the same files:

| File | Holds |
|---|---|
| `/etc/thinfloe/time` | the checked copy of `generated/time`; absent = automatic. `dhcp-timezone` reads it |
| `/etc/localtime` | `../usr/share/zoneinfo/<zone>` |
| `/etc/chrony/sources.d/thinfloe.sources` | `server <name> iburst` per menu server; with it, `ubuntu-ntp-pools.sources` is renamed to `ubuntu-ntp-pools.sources.thinfloe-off` (chrony reads only `*.sources`) and back when the servers go |
| `/run/chrony-dhcp/thinfloe.sources` | `server <address> iburst` per DHCP server, written by `dhcp-timezone` |
| `/run/thinfloe/state/dhcp-timezone` | the zone `dhcp-timezone` set last, for the band's "from DHCP" |

- **At boot:** `install_local_time()` in `90thinfloe/thinfloe-lib.sh`, called from `setup-overlay.sh` after `install_local_network`, before switch-root (the rule "per-machine network config is installed by the initramfs, never by a unit"). It is lenient: a bad line is logged with `tf_log` (values are never logged) and skipped, a link on the path is refused, it always returns 0. It uses builtins and `ln`, `mv`, `mkdir` only. The rootfs is a RAM overlay, so every boot starts from the image's pools file and repeats the rename.
- **Live:** `sudo -n /usr/bin/thinfloe-time apply`, run by the menu after it wrote `[time]`. It reads only `generated/time` of the home of tfuser (from the passwd entry, never `$HOME`), refuses a link on the path, a file that is not regular or is over 64 KiB, and any bad line, before it changes anything. Then it writes `/etc/thinfloe/time` and the chrony file, runs `timedatectl set-timezone -- <zone>` (or `UTC` when a menu zone goes), removes `/run/chrony-dhcp/thinfloe.sources` when the menu names servers (so a failed watcher restart cannot leave chrony on the DHCP servers), restarts `thinfloe-dhcp-timezone.service` (which reads the leases again: in automatic mode it sets the DHCP zone and writes the DHCP servers) and runs `chronyc reload sources` only when a sources file was written or removed, or the last reload failed (`/run/thinfloe/time.reload-pending`); a zone change alone does not touch chrony. The menu waits 100 s for it: the 30 s lock wait plus three tool calls of 20 s. It prints `{"result": "ok"|"failed", "reason": …}`; exit 0, 1, 2. No sudoers rule was added: tfuser already has `NOPASSWD:ALL`.

When the store write fails, the band shows the setting `config.toml` holds again. When the write succeeds and `thinfloe-time` fails, the setting stays and the band says `Saved, in effect after a restart: <reason>`: the initramfs installs it at the next start.

## The DHCP watcher

`thinfloe-dhcp-timezone.service` runs `/usr/libexec/thinfloe/dhcp-timezone --watch` as root (`After=systemd-networkd.service chrony.service`). networkd would set the zone itself through `timedated`, which needs polkit, and the image has none. The drop-in `overlay/etc/systemd/network/10-netplan-eth.network.d/50-timezone.conf` makes networkd ask for option 101 on the `eth` profile of `/etc/netplan/ethernet.yaml`; profiles from `~/.config/thinfloe/generated/wifi.yaml` have user-chosen ids and get none.

**Zone.** The script takes the lease's `TIMEZONE=` only if it is 1 to 64 characters of letters, digits and `/ _ + -`, has no `..`, no leading `/` or `-`, and names a TZif file whose `realpath` lies inside `/usr/share/zoneinfo`; then it runs `timedatectl set-timezone -- <zone>`, logs `thinfloe: time zone <zone> from DHCP` and writes `/run/thinfloe/state/dhcp-timezone`. Anything else logs `thinfloe: ignored DHCP time zone '<value cut to 64, printable>': <why>` and changes nothing. With a `zone=` line in `/etc/thinfloe/time` it sets nothing and logs once per zone `thinfloe: DHCP time zone <zone> not used: the zone is set in the menu`. With several leases the last one in glob order that carries a valid zone wins. The `from DHCP` line is logged only when the zone differs from the one the process set last; a restart logs it once more (accepted).

**NTP.** It collects the `NTP=` addresses of all leases (IPv4 or IPv6 literals only, at most 8, glob order, no repeats; anything else logs `thinfloe: ignored DHCP NTP server '<value>': not an IP address`), writes `/run/chrony-dhcp/thinfloe.sources` atomically when its content changes, logs `thinfloe: NTP servers … from DHCP` and runs `chronyc reload sources`. With `ntp=` lines in `/etc/thinfloe/time`, or no servers in any lease, the file is removed (`thinfloe: no NTP servers from DHCP`).

**Watching.** The script starts `inotifywait -m` on `/run/systemd/netif/leases/` (from `inotify-tools`), waits for its `Watches established.` line, reads the leases already there (a fast lease, or the initramfs lease on netboot), and reads them again after each change, once per burst (0.5 s of quiet). A change made during a read waits in the pipe, so none is lost. If the directory does not exist yet, it watches `/run/systemd/netif/` until networkd creates it; it never creates it itself. A missing `/run/systemd/netif/` logs `thinfloe: dhcp-timezone: no directory … to wait in for the leases` and fails, and so does the removal of the directory the watcher waits in. When `inotifywait` ends or the lease directory itself is removed or moved, the script exits 1 and `Restart=on-failure` starts it again (a stop with SIGTERM exits 0); `StartLimitIntervalSec=0` keeps the restarts from tripping the start limit. Without `--watch` the script reads the leases once. Up to 4.5.0 a `PathChanged=` path unit started a oneshot run instead: a path unit stops watching while its service runs and does not look again when it re-arms, so a lease written during a run stayed unread until the next renewal. The units carry no `Before=` on a sysinit unit.

**Netboot:** the initramfs's networkd runs dracut's default network file (`/run/systemd/network/zzzz-dracut-default.network`, no `ip=`), so `90thinfloe/module-setup.sh` installs a drop-in `zzzz-dracut-default.network.d/50-timezone.conf` (`UseTimezone=yes`) in the initrd; the lease it writes then carries `TIMEZONE=`, it survives the switch-root in `/run/systemd/netif/leases/`, and the watcher's first read applies it. (An `ip=` on the command line would use a generated file the drop-in does not cover.) The netboot home carries `generated/time` like a stick's.

## The Time band

On Settings → Network, between DNS and Public IP address; see [menu.md](menu.md). The status (zone, its source, `chronyc -c -n tracking`, `chronyc -c -N sources`) is read as the user on the tab's status poll, 2 s per chronyc call; chronyd answers monitoring requests from localhost without root.

## Tests

- `test/integration/test-thinfloe-time.sh`: `thinfloe-time apply` with stub `timedatectl`, `systemctl`, `chronyc`: a zone, back to automatic, servers and the pools rename, back again, a failed reload and its retry, no reload for a zone change, the DHCP servers file removed when the watcher restart fails, the menu timeout against the tool's constants, and hostile files (links, a FIFO, over 64 KiB, path and unknown zones, two zones, bad servers, nine servers, unknown keys, not UTF-8), each exit 1 with nothing changed or called.
- `test/integration/test-dhcp-timezone.sh`: hostile zones, stub `timedatectl`; `--watch` with a lease written during a read, a late lease directory, a repeated zone, a removed lease, `inotifywait` ending, SIGTERM, the directory removed, two leases with different zones, no parent directory; the state file; DHCP NTP written, unchanged, hostile, more than 8, removed; the menu's servers and zone win, also over a renewal.
- `test/integration/test-initramfs-home.sh`: `install_local_time` (zone, UTC, servers and rename, unknown and path zones skipped, bad server lines skipped, at most 8, links refused, no file) and once more under the initramfs's PATH.
- `test-session-packages.sh`: `thinfloe-time` in the image, both `sourcedir` lines in `chrony.conf`, the pools file and `zone.tab` present, no timesyncd.
- Menu (`cargo test`): `timecfg` (zone.tab, validation, the file), `timetab` (chronyc output recorded on the thin client, the lines), `timeband` (the selects, the field, failed saves), `jobs::time_save_writes_then_applies`, the menu's queue and tab-leave commit, the band in `ui.rs`, and `a_zone_change_reaches_the_clock_without_a_restart`.
- `make qemu-smoke-timezone` and `make qemu-smoke-timezone-netboot`: dnsmasq on a tap in `podman unshare unshare --net` sends option 101 and option 42 to a booted guest; the guest sets the zone and its `/run/chrony-dhcp/thinfloe.sources` names the server (a bare `unshare -rn` forbids the `setgroups` call dnsmasq makes at start-up).
