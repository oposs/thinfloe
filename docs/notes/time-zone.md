This note covers how the machine's time zone is chosen: `TZ=` in the home, the DHCP option 101 helper, netboot, and the tests.

**Time zone.** Order: `TZ=` in `~/.config/thinfloe/environment` (exported by `10-thinfloe-session.sh` with `set -a`, so it reaches labwc, `thinfloe-session` and the menu), else the DHCP zone, else UTC. An invalid `TZ=` gives UTC, not the DHCP zone, as glibc does. The drop-in `overlay/etc/systemd/network/10-netplan-eth.network.d/50-timezone.conf` makes networkd ask for option 101 on the `eth` profile of `/etc/netplan/ethernet.yaml`; profiles from `~/.config/thinfloe/generated/wifi.yaml` have user-chosen ids and get none. networkd would set the zone itself through `timedated`, which needs polkit, and the image has none, so `thinfloe-dhcp-timezone.service` runs `/usr/libexec/thinfloe/dhcp-timezone --watch` as root. That script takes the lease's `TIMEZONE=` only if it is 1 to 64 characters of letters, digits and `/ _ + -`, has no `..`, no leading `/` or `-`, and names a TZif file whose `realpath` lies inside `/usr/share/zoneinfo`; then it runs `timedatectl set-timezone -- <zone>` and logs `thinfloe: time zone <zone> from DHCP`. Anything else logs `thinfloe: ignored DHCP time zone '<value cut to 64, printable>': <why>` and changes nothing. With `--watch` the script runs for the whole boot: it starts `inotifywait -m` on `/run/systemd/netif/leases/` (from `inotify-tools`), waits for its `Watches established.` line, reads the leases already there (a fast lease, or the initramfs lease on netboot), and reads them again after each change, once per burst (0.5 s of quiet). A change made during a read waits in the pipe, so none is lost. If the directory does not exist yet, it watches `/run/systemd/netif/` until networkd creates it; it never creates it itself. With several leases the last one in glob order that carries a valid zone wins, and only that zone is set. The `from DHCP` line is logged only when that zone differs from the one the process set last, so a renewal does not repeat it; a restart of the service logs it once more (accepted). A missing `/run/systemd/netif/` logs `thinfloe: dhcp-timezone: no directory … to wait in for the leases` and fails, and so does the removal of the directory the watcher waits in. When `inotifywait` ends or the lease directory itself is removed or moved, the script exits 1 and `Restart=on-failure` starts it again (a stop with SIGTERM exits 0, so the unit is not left failed); `StartLimitIntervalSec=0` keeps the restarts from tripping the start limit. Without `--watch` the script reads the leases once. Up to 4.5.0 a `PathChanged=` path unit started a oneshot run instead: a path unit stops watching while its service runs and does not look again when it re-arms, so a lease written during a run stayed unread until the next renewal, hours later, and `make qemu-smoke-timezone` failed now and then. The units carry no `Before=` on a sysinit unit. **Netboot:** the initramfs's networkd runs dracut's default network file (`/run/systemd/network/zzzz-dracut-default.network`, no `ip=`), so `90thinfloe/module-setup.sh` installs a drop-in `zzzz-dracut-default.network.d/50-timezone.conf` (`UseTimezone=yes`) in the initrd; the lease it writes then carries `TIMEZONE=`, it survives the switch-root in `/run/systemd/netif/leases/`, and the watcher's first read applies it. (An `ip=` on the command line would use a generated file the drop-in does not cover.) Guards: `test/integration/test-dhcp-timezone.sh` (hostile values, stub `timedatectl`; `--watch` with a lease written during a read, a late lease directory, a repeated zone, a removed lease, `inotifywait` ending, SIGTERM, the directory removed, two leases with different zones, no parent directory), `test-session-packages.sh` (no path unit, the service enabled, `inotifywait` present), the menu test `a_zone_change_reaches_the_clock_without_a_restart`, `make qemu-smoke-timezone` and `make qemu-smoke-timezone-netboot` (the same netbooted over HTTP from the namespace; dnsmasq on a tap in `podman unshare unshare --net` sends option 101 to a booted guest; a bare `unshare -rn` forbids the `setgroups` call dnsmasq makes at start-up).
