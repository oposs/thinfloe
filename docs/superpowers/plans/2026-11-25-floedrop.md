# FloeDrop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ThinFloe receives files from iPhones into `/media/tfuser/FloeDrop/inbox/<sender>/` and offers files put into `outbox/<device>/` to iPhones in range, over AirDrop, with an OSD note for each delivery.

**Architecture:** A new crate `src/thinfloe-share/` builds `thinfloe-share`, a tokio daemon that runs as tfuser on Owly's `owly-airdrop` library; `thinfloe-share --radio`, started by it through `sudo -n`, holds Owly's radio lease from `owlyd` and runs the BLE advertisement as root. Folder logic, names, card choice and the state file are sans-IO modules behind a `Transport` trait. The menu supervises the daemon with the Deskflow supervisor, owns `[share]` in `config.toml`, renders `generated/share`, shows the FloeDrop band on the Network tab; the OSD gains a text note panel fed by a datagram.

**Tech Stack:** Rust 1.96.0 (edition 2024); Owly v0.4.3 crates `owly-airdrop` (features `tokio`, `mdns`) and `owlyd` (lib: D-Bus API) as git dependencies pinned to `rev = "21171d8f9a08bfa2c625a1fa338e877a67913e54"`; tokio, zbus 5 (tokio), rustls 0.23 (ring), `inotify` (stream), libc; bash integration tests; shadcn-egui for the band.

**Spec:** [docs/superpowers/specs/2026-11-24-airdrop-share-design.md](../specs/2026-11-24-airdrop-share-design.md). Read it first; this plan does not repeat its reasons.

## Global Constraints

- At most 4 cores: `CARGO_BUILD_JOBS=4`, `cargo … -j 4`, `cargo test -- --test-threads=4`; network/adversarial tests under `$(MEMCAP)` (`systemd-run --user --scope -q -p MemoryMax=2G --`).
- Owly pinned by commit `21171d8f9a08bfa2c625a1fa338e877a67913e54` (tag v0.4.3) in both `Cargo.toml` and the Dockerfile; `cargo build --locked`.
- No polkit, no NetworkManager in the image; never `AcquireDetached()`; the root helper uses plain `Acquire(0)` and releases a stale detached lease at start.
- Product name **FloeDrop** in UI, OSD, CHANGES and notes; program `thinfloe-share`, folder `/media/tfuser/FloeDrop`.
- tmpfs `media-tfuser-FloeDrop.mount`, options exactly `size=25%,uid=1001,gid=1001,mode=0755,nosuid,nodev,noexec`.
- Batch delay 3 s after the last change in an outbox folder; a gone device's empty folder removed after 60 s; OSD note shown 4 s.
- Every offer ends with the folder's offered entries deleted, whatever the outcome.
- `config.toml` written only by the menu (`store.rs`); the daemon reads only `generated/share`.
- Contract files atomic, tab-separated, readers ignore unknown trailing fields.
- UI colours from the theme, sizes from `brand.rs` (`ui_code_has_no_style_literals` stays green); UI text in Simplified Technical English.
- New build inputs listed in the `Makefile` prerequisites; `test-container-inputs.sh` covers them.
- `CHANGES.md` lines under `## [Unreleased]`, no release header; commit per task, Conventional-Commit subject, `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A file still being copied from the remote session when the 3 s timer fires** (a 2 GB video over ThinLinc's drive redirection writes for minutes) → it is not offered half-written: an entry with an open writer or an mtime younger than 3 s restarts the timer (Task 6 test `a_file_still_growing_holds_the_batch`).
2. **Two iPhones both named "iPhone"** → two folders `iPhone` and `iPhone (2)`, each bound to its own service ID; a file in one never goes to the other (Task 3 test `same_name_gets_a_suffix`, Task 6 test `folders_follow_the_service_id`).
3. **Sender name with `/`, `..`, a newline, 300 bytes of emoji** → one safe folder name, at most 64 bytes, never outside `inbox/` (Task 3 test `hostile_names_stay_inside`).
4. **The tmpfs fills during an upload that `/Ask` said would fit** (the outbox grew meanwhile) → the upload fails, its staged files are removed, the OSD shows the warning note, nothing half-written in `inbox/` (Task 5 test `a_full_disk_mid_upload_leaves_nothing`).
5. **The stick is pulled while the radio is up** → `owlyd` drops the lease, the helper reports `error`, the daemon writes `error` to the state file and the supervisor's back-off restarts it; the built-in card is not taken (Task 7 test `lease_lost_is_an_error_line`, Task 4 test `a_configured_card_is_never_taken`).
