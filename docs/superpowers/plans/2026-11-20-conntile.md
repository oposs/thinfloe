# Connection Element Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Connection status element shows labels left and values right, the VPN row only when up, and adds Gateway, DNS, Traffic and Uptime rows.

**Architecture:** The once-a-second network sampler (`netstat.rs`) also reads the DNS servers and `/proc/uptime` and hands the interface's byte counters through the snapshot; `status/connection.rs` builds the eight rows from it and draws them right-aligned, in one column (1x2) or two (2x1).

**Tech Stack:** Rust, egui, shadcn-egui (`src/thinfloe-menu`).

**Spec:** `docs/superpowers/specs/2026-11-20-conntile-design.md`

## Review Focus

- A machine with no default route (gateway `None`) and no resolv.conf: Gateway and DNS rows say `none` in the warning colour, never vanish or panic. Test: `unknown_facts_warn_measures_drop_out` (Task 2).
- An interface replaced mid-session (counters go back): Traffic shows the new interface's counters at once, no stale total. Test: `a_snapshot_carries_the_last_totals_and_uptime` pushes a lower counter (Task 1).
- IPv6 DNS server or public address of 39 chars in the 2x1 column: cut at the column's right padding, never into the other column. Test: `connection_draws_inside_its_rect_at_every_size` and `no_text_overlaps_another_or_leaves_the_element` with hostile data (Task 2).
- `/proc/uptime` unreadable or nonsense: no Uptime row. Test: `unknown_facts_warn_measures_drop_out` (Task 2) and `a_reading_carries_dns_counters_and_uptime` with junk uptime (Task 1).
- Odd row counts in 2x1 (5, 7 rows): the left column holds Link IPv4 Gateway DNS, the right the rest from the top, rows level across (review: a `ceil(n/2)` split moved rows between columns). Test: `the_wide_size_splits_rows_in_two_level_columns` (Task 2).
