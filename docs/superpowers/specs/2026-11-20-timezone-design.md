# Time zone and NTP settings on the Network tab

## Intent

The owner tested 4.6.0 on a real thin client: the clock shows the wrong
zone, because the owner's network does not hand out a time zone by DHCP.
Today the only way to set a zone is a hand-written `TZ=` in
`~/.config/thinfloe/environment`.

The owner asked for (as relayed by the controller):

- a time zone setting on the Network screen of the menu (Settings →
  Network);
- a check that NTP works (is systemd-timesyncd in the image and running?
  which servers does it use?), and an NTP server setting.

## What the thin client shows (2026-11-20, read-only ssh, 4.6.0)

- `timedatectl`: `Time zone: UTC`, `System clock synchronized: yes`,
  `NTP service: active`. `/etc/localtime -> /usr/share/zoneinfo/UTC`.
- The NTP client is **chrony**, not systemd-timesyncd (timesyncd is not in
  the image). It syncs with the Ubuntu NTS pools
  (`/etc/chrony/sources.d/ubuntu-ntp-pools.sources`, `nts prefer`).
- The DHCP lease carries `NTP=195.176.26.215`, and `networkctl` lists it,
  but chrony does not use it. chrony reads DHCP servers from
  `sourcedir /run/chrony-dhcp`, which dhclient hooks or NetworkManager
  fill; ThinFloe has neither, so that directory never exists. On a network
  without internet access the clock would not be synchronised at all.
- The lease has no `TIMEZONE=`; `thinfloe-dhcp-timezone` logged nothing.
- `chronyc -c tracking` and `chronyc -c -N sources` answer as tfuser (no
  root needed: chronyd allows monitoring commands from localhost).
- `/usr/share/zoneinfo/zone.tab` is in the image (418 zones).
- tfuser has `NOPASSWD:ALL`; there is no file in `/etc/sudoers.d`.

Raw output: `/scratch/oetiker/claude-tmp/ui-round/timezone/thinclient.txt`.

## Goals

- Pick the machine's time zone in Settings → Network; it takes effect at
  once (menu clock, journal) and survives a restart (home archive).
- See whether the clock is synchronised, with which server, and which
  servers chrony uses.
- Set NTP servers for networks that need their own.
- In "automatic" mode, use the NTP servers DHCP sends (a bug today).

## Non-goals

- No switch from chrony to timesyncd.
- No per-session zone UI; the hand-written `TZ=` stays as it is.
- No NTS options for user servers (plain NTP, as DHCP servers are).
- No manual setting of the clock.

## Anti-goals

- A zone set in the menu that DHCP silently overrides.
- A root tool that takes a path or a chrony directive from the home.
- A Network-tab Apply (netplan apply, the remote-session confirm) for a
  time change: a time change never cuts the network.

## Approaches considered

1. **System zone, root apply, initramfs install** *(chosen)*. The menu
   stores `[time]` in `config.toml` and renders `generated/time`. A new
   root tool `thinfloe-time apply` installs it live (`timedatectl
   set-timezone`, chrony sources, `chronyc reload sources`); at boot the
   initramfs installs it before switch-root, as it does with the netplan
   files. Every process without `TZ` gets the zone, including the journal
   and the menu clock, live.
2. **`TZ=` in `generated/environment`.** No root, but only processes
   started after a session restart see it; the journal and system tools
   stay on UTC; the menu itself would have to re-exec. NTP still needs
   root. Rejected.
3. **A systemd unit `Before=chrony.service` that installs the settings.**
   Would reuse the Python tool at boot, but goes against the standing
   constraint "per-machine network config is installed by the initramfs,
   never by a unit". Rejected *(architect)*.

## Design

### Precedence *(architect)*

- System time zone: zone set in the menu > DHCP zone > UTC. "Automatic"
  (no zone set) is today's behaviour.
- Session: a hand-written `TZ=` in `~/.config/thinfloe/environment` still
  wins inside the session; the tab says so when the menu's own `TZ` is
  set (see UI).
- NTP: servers set in the menu replace all others (the Ubuntu pools and
  the DHCP servers). Empty ("automatic"): the DHCP servers plus the Ubuntu
  pools. Reason: a network with its own NTP server usually wants only that
  one; mixing it with internet pools makes the choice unpredictable.

### Data

`config.toml`, new table, written only by the menu (`store.rs`):

```toml
[time]
zone = "Europe/Zurich"   # absent: automatic
ntp = ["ntp.example.ch", "10.1.2.3"]   # empty or absent: automatic
```

`generated/time` (mode 644, generated header, absent when both are
automatic), one key per line, readable by shell and Python:

```
# Generated by the ThinFloe menu ...
zone=Europe/Zurich
ntp=ntp.example.ch
ntp=10.1.2.3
```

`convert::from_generated` reads it back when `config.toml` is broken.
`Table::Time` feeds `["time"]`.

Root side, written only by the initramfs and `thinfloe-time apply`:

- `/etc/thinfloe/time`: the validated copy of `generated/time` (same
  format, no header needed). Absent = automatic. `dhcp-timezone` reads it.
- `/etc/localtime`: `../usr/share/zoneinfo/<zone>` (what timedatectl
  writes).
- `/etc/chrony/sources.d/thinfloe.sources`: `server <name> iburst` per
  menu server; with it present, `ubuntu-ntp-pools.sources` is renamed to
  `ubuntu-ntp-pools.sources.thinfloe-off` (chrony reads only `*.sources`),
  and renamed back when the menu servers go. The rootfs is a RAM overlay,
  so each boot starts from the image's file and the initramfs repeats the
  rename.
- `/run/chrony-dhcp/thinfloe.sources`: `server <addr> iburst` per DHCP NTP
  server, written by `dhcp-timezone` (see below).
- `/run/thinfloe/state/dhcp-timezone`: the zone `dhcp-timezone` set last
  (for the "from DHCP" label).

### Validation *(architect)*

- Zone (menu, `thinfloe-time`, initramfs): the third column of a
  non-comment line of `/usr/share/zoneinfo/zone.tab`, or `UTC`. The menu
  offers only those; the root tools check membership, which rules out
  paths, `..` and links by construction. The DHCP rule in `dhcp-timezone`
  stays as it is (a DHCP server may send any valid TZif name).
- NTP server (menu, `thinfloe-time`): an IPv4 or IPv6 literal, or a host
  name of at most 253 characters, labels of 1 to 63 letters, digits and
  `-`, not starting or ending with `-`, no trailing dot. At most 8 servers.
  The initramfs checks the character set (`A-Za-z0-9.:-`), no leading
  `-`, and the length; with one token per line nothing else can reach the
  chrony file.
- DHCP NTP values (`dhcp-timezone`): IPv4 or IPv6 literals only (networkd
  writes addresses), at most 8, others logged and dropped.
- `thinfloe-time apply` is strict: one bad line, a symlink, a file over
  64 KiB or not a regular file fails with a reason and changes nothing.
  The initramfs is lenient: a bad line is logged (`tf_log`) and skipped,
  the boot goes on.

### Boot: `install_local_time()` in `thinfloe-lib.sh`

Called from `setup-overlay.sh` after `install_local_network`. Reads
`$NEWROOT/home/tfuser/.config/thinfloe/generated/time` (refuses a symlink;
a legacy home has none), validates, writes `$NEWROOT/etc/thinfloe/time`,
the `/etc/localtime` link, the chrony file and the rename. Builtins plus
`ln`, `mv`, `rm`, `mkdir` only (dracut base set; guarded by
`test-initramfs-commands.sh`). No `exit`.

### Live: `/usr/bin/thinfloe-time apply` (Python, as `thinfloe-network`)

Run by the menu as `sudo -n /usr/bin/thinfloe-time apply`. No new sudoers
rule: tfuser already has `NOPASSWD:ALL`, and the tool takes no argument
from the caller beyond the command word; it reads the file of tfuser's
home itself (`getent passwd tfuser`, `TF_TIME_HOME` for tests). Steps:
read and validate `generated/time` (strict); write `/etc/thinfloe/time`
atomically (or remove it); zone set → `timedatectl set-timezone -- <zone>`,
automatic → `timedatectl set-timezone UTC`; chrony file and rename;
`systemctl restart thinfloe-dhcp-timezone.service` (it reads the leases
again at start: in automatic mode it sets the DHCP zone and writes the
DHCP NTP file, otherwise it leaves them); `chronyc reload sources`. Prints
`{"result": "ok"|"failed", "reason": ...}` like `thinfloe-network`; exit
0/1/2. A lock in `/run/thinfloe/time.lock`. Commands, paths and tools are
overridable through `TF_TIME_*` variables for the offline test.

### DHCP: `dhcp-timezone` grows the NTP half *(architect)*

The watcher already reads every lease on each change. It now also:

- skips the zone when `/etc/thinfloe/time` has a `zone=` line (logs once
  `thinfloe: DHCP time zone <z> not used: the zone is set in the menu`);
- writes `/run/thinfloe/state/dhcp-timezone` when it sets a zone;
- collects `NTP=` of all leases (addresses only, at most 8, glob order),
  writes `/run/chrony-dhcp/thinfloe.sources` atomically when the content
  changes and runs `chronyc reload sources`; with `ntp=` lines in
  `/etc/thinfloe/time` the file is removed instead.

The script and unit keep their names *(architect: renaming churns the
tests, the unit name in logs and the history; the docstring and the note
say it handles NTP too)*.

### Status (menu, no root)

The Network tab's status poll (`Job::NetStatus`, the 5 s poll) also runs
`chronyc -c tracking` and `chronyc -c -N sources` (timeout 2 s each) and
reads `/etc/localtime`, `/etc/thinfloe/time` and
`/run/thinfloe/state/dhcp-timezone`. The result rides
`netdetail::Details` as `time: TimeStatus { zone, zone_source:
Menu|Dhcp|Default, synced: Option<SyncInfo{server, offset_s, stratum}>,
servers: Vec<(name, state)>, error }`. Parsing lives in a new pure module
`timetab.rs` with unit tests on recorded chronyc output.

### UI: a "Time" band on the Network tab *(architect)*

Placed after "DNS", before "Public IP address". Saved at once like the
public IP switch, independent of the Network Apply; enabled before the
network files are read and while a network Apply runs; disabled while a
time apply runs ("Applying…" note).

```
Time
  Time zone      [ Europe        v ] [ Zurich              v ]
                 In use: Europe/Zurich (UTC+01:00), set here.
  NTP servers    [ ntp.example.ch, 10.1.2.3                  ]
                 Empty: the servers DHCP sends and the Ubuntu pool.
  Clock          Synchronised with 2.ntp.ubuntu.com, 0.1 ms off.
                 Servers: 1.ntp.ubuntu.com, 2.ntp.ubuntu.com (in use),
                 195.176.26.215 (unreachable)
```

- Zone picker *(architect)*: two shadcn `Select`s, region then city,
  built from `zone.tab` (sorted; city label without the region, `_` as a
  space, `Argentina/Buenos_Aires` → `Argentina/Buenos Aires`). The region
  list starts with `Automatic` and `UTC`. The Select's type-ahead makes
  each list searchable by its first letter; shadcn-egui has no combobox,
  and porting one is out of proportion. Picking `Automatic` or `UTC`
  saves at once; picking a region shows the city list with the
  placeholder "Choose a city" and saves nothing until a city is picked.
- Zone line: `In use: <zone> (UTC±hh:mm), set here.` / `…, from DHCP.` /
  `UTC: DHCP sends no time zone.`; when the menu's `TZ` is set: `This
  session uses TZ=<value> from ~/.config/thinfloe/environment.`
- NTP field: saved when left or on Enter, Escape restores (the lookup
  address pattern; the pending-field slot is shared by the two fields).
  A refused value is named below and not saved: `Not used: <name> is not
  a host name or address.` / `At most 8 servers.`
- Clock line: `Synchronised with <server>, <offset> off.` /
  `Not synchronised yet.` / `The time service does not answer.`
- A failed apply shows its reason in the band (warn style), as the
  network Apply error does.

### Menu jobs

- `Job::TimeSave(TimeCfg)`: `store.update(Table::Time, …)`, then
  `sudo -n /usr/bin/thinfloe-time apply` (`Paths::time_cmd`,
  `TF_TIME_CMD`, timeout 60 s), in its own process group like the other
  tools. One runs at a time, a newer request waits (as `PublicIpSave`).

## Tests

- Rust (`cargo test`): zone.tab parsing and region/city lists; zone and
  NTP validation (a table of good and hostile values); `[time]` round
  trip; `generated/time` render and `from_generated` read-back; chronyc
  CSV parsing (recorded from the thin client), status lines; `NetTab`
  events for the zone selects and the NTP field (commit, cancel, refuse);
  `TimeSave` serialisation.
- `test/integration/test-thinfloe-time.sh` (new): stub `timedatectl`,
  `systemctl`, `chronyc`; apply with a zone, automatic, servers, back to
  automatic (rename back); hostile files (symlink, bad zone, path zone,
  bad server, nine servers, oversize) fail and change nothing; exit codes.
- `test-dhcp-timezone.sh`: menu zone wins over the DHCP zone; DHCP NTP
  file written, rewritten only on change, removed when menu servers are
  set; hostile `NTP=` values; the state file.
- `test-initramfs-home.sh`: `install_local_time` with the restricted PATH:
  zone link, chrony file and rename, a bad line skipped, symlink refused,
  no file = nothing changed.
- `test-initramfs-commands.sh`: covers the new hook commands as is.
- `test-session-packages.sh`: `thinfloe-time` present and executable;
  `chrony.conf` still has `sourcedir /run/chrony-dhcp` and
  `sourcedir /etc/chrony/sources.d`; `ubuntu-ntp-pools.sources` and
  `zone.tab` present; no timesyncd.
- `make qemu-smoke-timezone`: dnsmasq also sends option 42; the guest's
  `/run/chrony-dhcp/thinfloe.sources` names it and `chronyc -c -N sources`
  lists it.
